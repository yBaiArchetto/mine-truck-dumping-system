# 线框页面 · 低保真线框原型

> 项目：矿井货车倒矿智能管控系统开发项目
> 招标人：华盛矿业（集团）有限公司 · 招标编号 HXKY-ZB-2026-0325
> 需求基线：需求基线草案 V0.9（需求分析会议纪要，2026-10-15）
> 本目录用途：软件项目管理课程实验 —— 依托 GitHub 进行项目版本管理的**低保真线框基线**

本目录存放系统的**低保真线框（Lo-Fi Wireframe）**。线框页面只回答三个问题：**页面有哪些、信息如何分区、操作如何流转**，不讨论配色与视觉细节。它是需求评审与信息架构讨论的主要载体，也是高保真原型（[`原型页面`](../原型页面/README.md)）的结构依据。

全部页面为**零外部依赖**的纯 HTML + 内联 CSS/JS，断网、内网、U 盘拷贝均可直接打开，适合在评审会现场演示。

## 一、目录结构

```
├── home.html          # 工作台总览

├── recognition.html   # 车牌识别与自动计次

├── mobile.html        # 移动端 H5 演示

```

8 个文件平铺存放，无子目录、无构建步骤、无 `package.json`，打开即为最终形态。

## 三、线框图规范

### 3.1 视觉约定

| 项目        | 规范                                                         |
| ----------- | ------------------------------------------------------------ |
| 配色        | 纯灰度：底 `#f7f7f7`、文字 `#333`、次要文字 `#999`、边框 `#ccc` / `#ddd`；**不使用任何主题色**，避免评审被颜色干扰 |
| 强调手段    | 仅用线宽、边框虚实、色块深浅、字号字重区分层级（如紧急告警用 2px 实线边框） |
| 图表        | 统一使用虚线占位块（`.chart-ph`），块内注明「图形类型 + 图例 + 数据维度」，不绘制伪数据曲线 |
| 图片 / 视频 | 使用棋盘格或网格底纹占位块，并标注「[ 视频画面占位 ]」等文字 |
| 布局        | 侧栏 240px + 顶栏 56px + 内容区；三栏栅格 `2fr 1fr`、`1fr 2fr 1fr`，间距 12–16px |
| 字体        | `system-ui / PingFang SC / Microsoft YaHei`；正文 12–13px，面板标题 13px，指标数值 20–22px |
| 响应式      | 1280px 以下多栏折叠，900px 以下隐藏侧栏                      |
| 页脚声明    | 每页页脚均标注「演示数据」；`home.html` 与 `project.html` 另附招标人与招标编号 |

### 3.2 占位块写法（便于统一检索与替换）

```html
<div class="chart-ph" style="height:260px;">
  [ 柱状 + 折线图占位 ]<br/>图例：倒矿车次 / 识别次数
</div>
```

占位块内**必须写明图形类型与数据维度**，评审时才能判断「这里要展示什么」；这是线框与原型之间可追溯的关键约定。

## 四、已实现交互

线框虽为低保真，但关键业务路径可用鼠标走通，便于评审时验证流程是否合理：

| 页面               | 交互                                                         |
| ------------------ | ------------------------------------------------------------ |
| 全部               | 左侧导航跳转与当前页高亮、栅格响应式折叠                     |
| `home.html`        | 统计周期切换按钮组                                           |
| `dashboard.html`   | 顶栏实时时钟每秒刷新                                         |
| `recognition.html` | 按车牌 / 点位 / 状态筛选与重置、打开记录详情弹窗（遮罩 / ✕ / 取消均可关闭）、确认识别结果与导出提示 |
| `vehicles.html`    | 在途车辆列表点击 → 当前车牌、司机、状态、流程进度、轨迹事件同步更新 |
| `alarms.html`      | 按级别 / 类型 / 状态筛选、打开复核弹窗、提交复核结论后列表状态回写 |
| `statistics.html`  | 周期切换、生成报表与批量导出提示（不生成真实文件）           |
| `mobile.html`      | 底部标签切换三屏、快捷操作与「立即补录」反馈                 |
| `project.html`     | 5 个标签页切换                                               |

所有反馈以页面内提示（Toast / 弹窗）呈现，**不调用后端接口、不写入任何数据**，刷新即回到初始状态。

## 五、打开与评审方式

1. **打开**：双击任意 `.html` 文件，或拖入 Chrome / Edge 窗口；推荐分辨率 1440×900，大屏页建议 1920×1080。
2. **零依赖**：无 CDN、无字体文件、无图片资源，断网环境与甲方内网均可完整显示，适合评审会现场投屏。
3. **评审建议**：
   - 按导航顺序逐页走查，重点确认「信息是否齐全、字段是否够用、操作入口位置是否合理」；
   - 图表占位块逐块确认「图形类型是否合适」；
   - 评审意见按「页面文件名 + 模块名」编号登记，例如 `alarms.html 复核弹窗 → 需增加处置附件上传`；
   - 意见闭环后回归本目录更新线框，再同步到高保真原型，保证两套页面信息架构一致。

## 七、与「原型页面」的对应关系

两套页面**文件名一一对应、信息架构一致**，形成「先线框评审、后原型确认」的双层基线：

| 对比项   | 线框页面（本目录）               | [原型页面](../原型页面/README.md)   |
| -------- | -------------------------------- | ----------------------------------- |
| 保真度   | 低保真，灰度线框                 | 高保真，接近最终界面                |
| 图表     | 虚线占位 + 图形类型说明          | ECharts 真实渲染                    |
| 视觉     | 纯灰度、1px 边框、无主题色       | 深色侧栏 + 青色主色 + 圆角卡片      |
| 外部依赖 | 无                               | CDN（Tailwind / Iconify / ECharts） |
| 离线可用 | ✅ 完全可用                       | ⚠ 需先做资源本地化                  |
| 主要用途 | 需求评审、信息架构确认、离线演示 | 甲方演示、视觉确认、开发对照        |
| 迭代节奏 | 需求变更后先改线框               | 线框确认后同步原型                  |

**同步原则**：任何信息架构层面的变更（增删模块、调整字段、改动操作流程）先落线框；纯视觉层面的调整只改原型，并回写线框的说明文字。

## 八、Git / GitHub 版本管理约定

本目录是课程实验「利用 GitHub 进行项目版本管理」的受管内容之一。线框文件体积小、变更频繁，最适合用来练习**小步提交、分支开发与版本标签**。

### 8.1 纳入仓库的范围

| 内容                                                | 是否提交 | 说明                  |
| --------------------------------------------------- | -------- | --------------------- |
| `线框页面/*.html`                                   | ✅ 提交   | 8 个线框页面          |
| `线框页面/README.md`                                | ✅ 提交   | 目录说明与规范        |
| 浏览器缓存、`.DS_Store`、`Thumbs.db`、`desktop.ini` | ❌ 忽略   | 系统临时文件          |
| `招投标书及合同，需求文件/~$*.docx`                 | ❌ 忽略   | Word 打开产生的锁文件 |

仓库根目录 `.gitignore` 建议至少包含：

```gitignore
# 系统与编辑器
.DS_Store
Thumbs.db
desktop.ini
.vscode/
.idea/

# Office 临时锁文件
~$*

# 依赖与构建产物
node_modules/
dist/
```

### 8.2 分支策略

| 分支                       | 用途         | 说明                                                         |
| -------------------------- | ------------ | ------------------------------------------------------------ |
| `main`                     | 稳定基线     | 评审通过的线框版本，按里程碑打标签                           |
| `develop`                  | 日常集成     | 各分支汇总，供评审前联调走查                                 |
| `feature/wireframe-<页面>` | 单页线框迭代 | 如 `feature/wireframe-alarms`、`feature/wireframe-master-data` |
| `fix/wireframe-<问题>`     | 线框缺陷修复 | 如 `fix/wireframe-mobile-tabbar`                             |
| `docs/<主题>`              | 文档维护     | 如 `docs/wireframe-readme`                                   |

### 8.3 提交信息规范

采用 `type(scope): 简述`，一次提交只改一个页面或一件事：

| type       | 含义                   | 示例                                           |
| ---------- | ---------------------- | ---------------------------------------------- |
| `feat`     | 新增页面 / 模块 / 交互 | `feat(wireframe): 新增基础数据管理线框页`      |
| `fix`      | 修复线框缺陷           | `fix(wireframe): 修复告警筛选后列表计数未更新` |
| `style`    | 仅排版 / 间距调整      | `style(wireframe): 统一面板标题字号`           |
| `refactor` | 结构调整（表现不变）   | `refactor(wireframe): 抽出通用栅格类名`        |
| `docs`     | 文档变更               | `docs(wireframe): 补充需求覆盖度分析`          |
| `chore`    | 杂项                   | `chore: 更新 .gitignore 忽略 Office 锁文件`    |

示例提交序列（可写入实验报告的提交历史）：

```bash
git init
git branch -M main
git add 线框页面 原型页面
git commit -m "chore: 初始化线框与原型页面"

git add 线框页面/home.html
git commit -m "feat(wireframe): 提交工作台总览线框"

git add 线框页面/
git commit -m "feat(wireframe): 完成 8 个页面低保真线框"

git add 线框页面/README.md
git commit -m "docs(wireframe): 编写线框页面 README"

git checkout -b feature/wireframe-master-data
# ……补充基础数据管理线框页……
git add 线框页面/master-data.html
git commit -m "feat(wireframe): 新增基础数据管理线框页"

git checkout main
git merge --no-ff feature/wireframe-master-data

git remote add origin https://github.com/<用户名>/<仓库名>.git
git push -u origin main
```

### 8.4 版本标签

```bash
git tag -a v0.9.0-wireframe -m "线框评审版本：8 个页面，覆盖 6/8 功能模块"
git push origin v0.9.0-wireframe
```

| 标签               | 含义                                      |
| ------------------ | ----------------------------------------- |
| `v0.9.0-wireframe` | 需求基线 V0.9 对应的线框评审版            |
| `v1.0.0-wireframe` | 评审意见闭环 + 补齐缺失模块后的线框冻结版 |

### 8.5 提交前自检清单

- [ ] 逐页打开，无横向滚动条、无样式错位、导航可跳转；
- [ ] 新增面板与字段已在页脚或 README 中说明用途，未引入真实业务数据；
- [ ] 图表占位块写明「图形类型 + 数据维度」；
- [ ] 与原型页面信息架构一致，差异已在 README 第七节说明；
- [ ] 未提交系统临时文件与 Office 锁文件；
- [ ] 提交信息符合规范，关键节点已打标签并记录 commit hash。

> 小提示：仓库路径含中文时，命令行操作建议加引号（如 `git add "线框页面/alarms.html"`）；GitHub 网页端可正常显示中文目录名。若线框与原型需同页对照，可在 `project.html` 或实验报告中使用相对链接互相引用。
