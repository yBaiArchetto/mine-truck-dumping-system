# 原型页面 · 高保真可交互原型

> 项目：矿井货车倒矿智能管控系统开发项目
> 招标人：华盛矿业（集团）有限公司 · 招标编号 HXKY-ZB-2026-0325
> 需求基线：需求基线草案 V0.9（需求分析会议纪要，2026-10-15）
> 本目录用途：软件项目管理课程实验 —— 依托 GitHub 进行项目版本管理的**高保真原型基线**

本目录存放系统的**高保真原型（Hi-Fi Prototype）**。与同级的 [`线框页面`](../线框页面/README.md) 相比，本目录重点表达**最终视觉风格、真实图表与完整交互路径**，用于向甲方演示系统形态、确认界面风格，并作为前后端开发与 UI 走查的对照基准。

## 四、运行与预览

### 4.1 打开方式

直接双击 `mine-truck-dumping-system/home.html`，或在浏览器地址栏打开本地文件路径即可。
推荐浏览器：Chrome / Edge 最新版；建议预览分辨率 1920×1080（大屏页）与 1440×900（管理端页面）。

### 4.2 外部依赖（重要）

原型页面通过 CDN 引用了三份脚本，并引用了 2 张由原型工具生成的现场示意图：

| 依赖                                  | 用途                   | 引用页面                                                     |
| ------------------------------------- | ---------------------- | ------------------------------------------------------------ |
| `tailwindcss.js`（modao.cc CDN）      | 原子化样式运行时       | 全部 8 页                                                    |
| `iconify-icon.min.js`（modao.cc CDN） | 图标渲染               | 全部 8 页                                                    |
| `echarts.min.js`（modao.cc CDN）      | 图表渲染               | home / dashboard / recognition / vehicles / alarms / statistics |
| 现场示意图 2 张（modao.cc media）     | 视频通道与抓拍画面背景 | home.html、recognition.html                                  |

因此：

- **联网环境**下可获得完整视觉与图表效果；
- **纯离线 / 甲方内网**环境下样式与图表会退化，需按下节做离线化处理；
- 面向客户的内网演示，建议优先使用 [`线框页面`](../线框页面/README.md)（零外部依赖），或先完成离线化改造。

### 4.3 离线化建议（后续迭代项）

1. 将三份 CDN 脚本与 2 张图片下载到本地，例如：
   `mine-truck-dumping-system/assets/vendor/tailwindcss.js`、`assets/vendor/iconify-icon.min.js`、`assets/vendor/echarts.min.js`、`assets/img/*.jpg`；
2. 批量把 8 个页面的 `<script src="https://modao.cc/...">` 改为相对路径 `assets/vendor/...`，`<img src="https://modao.cc/...">` 改为 `assets/img/...`；
3. 离线验证：断网后逐页打开，确认侧栏、图标、图表、背景图均正常；
4. 离线化改造应作为**独立提交**（`refactor(prototype): 本地化 CDN 依赖以支持内网演示`），便于评审时对比差异。

## 五、数据与口径说明

1. **全部为演示数据**：页面中的车牌号（豫 C·8F23 挂等）、司机、时间、车次、重量、置信度均为模拟值，不代表真实生产数据，页脚已作「演示数据」声明。
2. **关键业务口径**（与需求文档一致，供开发与测试对齐）：

| 口径         | 取值                                                         |
| ------------ | ------------------------------------------------------------ |
| 自动计次阈值 | 置信度 ≥ 90% 自动计次                                        |
| 人工复核区间 | 置信度 70%–90%，复核时限 20 秒/条                            |
| 识别失败判定 | 置信度 < 70%，由司磅员手动补录                               |
| 重复计数控制 | 同一车辆 5 分钟内重复识别自动去重                            |
| 告警分级     | 紧急 / 重要 / 一般；紧急 2 分钟内响应，重要 5 分钟内响应     |
| 定位精度     | 验收底线 ≤ 10 米，定位数据刷新间隔 5 秒                      |
| 性能指标     | 并发接入 ≥ 200 路、系统可用率 ≥ 99.9%、查询响应 ≤ 2 秒、功能实现率 100% |
| 交付与培训   | 文档 13 项、培训 3 场次不少于 12 课时、试运行 ≥ 2 个月       |

3. **数据来源**：`招投标书及合同，需求文件/` 目录中的招标书、投标书、技术开发（委托）合同，以及需求分析会议形成的需求基线草案 V0.9。涉及文档间冲突的条款（如质保期 12 个月 vs 18 个月、定位精度 ≤10 米 vs ≤1 米），在 `project.html` 的「待确认事项」标签页统一标注为待确认。

## 七、Git / GitHub 版本管理约定

本目录是课程实验「利用 GitHub 进行项目版本管理」的受管内容之一，约定如下。

### 7.1 纳入仓库的范围

| 内容                                                | 是否提交 | 说明                                          |
| --------------------------------------------------- | -------- | --------------------------------------------- |
| `mine-truck-dumping-system/*.html`                  | ✅ 提交   | 原型主体，8 个页面                            |
| `mine-truck-dumping-system/avatar/*.png`            | ✅ 提交   | 演示素材；若仓库体积敏感，可改为 Git LFS 管理 |
| 本 `README.md`                                      | ✅ 提交   | 目录说明与版本管理约定                        |
| 浏览器缓存、`.DS_Store`、`Thumbs.db`、`desktop.ini` | ❌ 忽略   | 系统临时文件                                  |
| `招投标书及合同，需求文件/~$*.docx`                 | ❌ 忽略   | Word 打开时产生的锁文件，非项目内容           |

建议在仓库根目录维护 `.gitignore`（至少包含）：

```gitignore
# 系统与编辑器
.DS_Store
Thumbs.db
desktop.ini
.vscode/
.idea/

# Office 临时锁文件
~$*

# 依赖与构建产物
node_modules/
dist/
```

### 7.2 分支策略

| 分支                   | 用途                 | 说明                                                 |
| ---------------------- | -------------------- | ---------------------------------------------------- |
| `main`                 | 稳定基线，可演示版本 | 仅接收经评审合并的变更，每个里程碑打标签             |
| `develop`              | 日常集成             | 每次交付评审前由 `main` 合入                         |
| `feature/proto-<页面>` | 单页面或单模块迭代   | 如 `feature/proto-dashboard`、`feature/proto-mobile` |
| `docs/<主题>`          | 文档与 README 维护   | 如 `docs/prototype-readme`                           |

### 7.3 提交信息规范

采用 `type(scope): 简述` 格式，中文简述、一次提交只做一件事：

| type       | 含义                 | 示例                                                 |
| ---------- | -------------------- | ---------------------------------------------------- |
| `feat`     | 新增页面或功能       | `feat(prototype): 新增可视化看板大屏页`              |
| `fix`      | 修复缺陷             | `fix(prototype): 修复告警复核弹窗关闭后状态未复位`   |
| `style`    | 仅样式/视觉调整      | `style(prototype): 统一指标卡圆角与间距`             |
| `refactor` | 结构调整（不改表现） | `refactor(prototype): 本地化 CDN 依赖以支持内网演示` |
| `docs`     | 文档变更             | `docs(prototype): 补充页面清单与数据口径说明`        |
| `chore`    | 杂项（素材、配置）   | `chore(prototype): 补充演示头像素材`                 |

示例提交序列（可写入实验报告的提交历史）：

```bash
git init
git add 原型页面 线框页面
git commit -m "chore: 初始化原型与线框页面"

git add 原型页面/mine-truck-dumping-system/home.html
git commit -m "feat(prototype): 提交工作台总览页"

git add 原型页面/mine-truck-dumping-system/
git commit -m "feat(prototype): 完成管理端 8 个页面原型"

git add 原型页面/README.md
git commit -m "docs(prototype): 编写原型页面 README"

git branch -M main
git remote add origin https://github.com/<用户名>/<仓库名>.git
git push -u origin main
```

### 7.4 版本标签

```bash
git tag -a v0.9.0-prototype -m "原型评审版本：8 个页面完成，待甲方确认视觉风格"
git push origin v0.9.0-prototype
```

| 标签               | 含义                                         |
| ------------------ | -------------------------------------------- |
| `v0.9.0-prototype` | 需求基线 V0.9 对应的原型评审版               |
| `v1.0.0-prototype` | 评审意见闭环后的原型冻结版，作为开发对照基准 |

### 7.5 提交前自检清单

- [ ] 逐页打开，确认无空白区块、无控制台报错、导航链接可跳转；
- [ ] 新增/修改页面的演示数据与口径说明一致（阈值、指标不得随意改动）；
- [ ] 未提交浏览器缓存、Office 锁文件（`~$*`）等无关文件；
- [ ] 提交信息符合 `type(scope): 简述` 规范，粒度适中；
- [ ] 关键节点已打标签，并在实验报告中记录对应提交号（commit hash）。

> 小提示：仓库路径含中文时，命令行操作建议加引号（如 `git add "原型页面/README.md"`）；GitHub 网页端可正常显示中文目录名。
