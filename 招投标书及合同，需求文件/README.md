# 招投标书及合同、需求文件

> 项目：矿井货车倒矿智能管控系统开发项目
> 招标人（甲方）：华盛矿业（集团）有限公司 · 招标编号：HXKY-ZB-2026-0325
> 本目录用途：存放项目**原始依据文件**，是需求基线与验收口径的唯一来源

本目录保存项目立项阶段的三份正式文件。系统的全部功能范围、性能指标、验收标准、售后承诺均以这三份文件为准；页面原型、线框与实施计划都是对它们的技术转译，不得反向覆盖原始条款。

## 二、文件的定位与阅读顺序

```
招标书  ── 甲方要什么（需求上限）
   ↓
投标书  ── 乙方承诺什么（可能高于招标要求，形成正偏离）
   ↓
合同    ── 双方最终约定什么（法律效力最高，验收以此为准）
   ↓
需求基线 V0.9（会议纪要整理）
   ↓
线框页面 → 原型页面 → 系统开发实施计划文档 → 进度计划（项目1.mpp）
```

评审或验收时，任何一条功能、指标、交付物都必须能回溯到上述链条中的某一环；无法回溯的，视为需求外新增。

## 五、使用规范

1. **原始文件只读**：本目录下的 `.docx` 为正式依据，不得直接修改内容。确需修订时另出「补充协议」或「变更单」，与原件一并归档，保留版本链。
2. **命名统一**：三份 Word 文件标题为「矿井货车倒矿**管理**系统」，而页面、原型、实施计划统一采用「矿井货车倒矿**智能管控**系统」。对外文档建议统一为后者，并在首次出现处注明二者为同一项目，避免验收时名称不一致。
3. **不提交 Word 锁文件**：用 Word 打开文件时会自动生成 `~$组 矿井货车倒矿管理系统-*.docx` 临时锁文件，属于本地缓存，**不应提交到版本库**。仓库根目录 `.gitignore` 已包含 `~$*` 规则。
4. **引用方式**：文档与报告引用条款时，写清「文件名 + 条款位置」，例如「合同第十九条」「投标书商务偏离表」，便于追溯。
5. **版本与基线**：文档未改动时，本目录内容随仓库标签冻结（如 `v0.9.0`）；一旦签署补充协议，需同步更新需求基线版本号并登记到根目录 README 的变更记录。
