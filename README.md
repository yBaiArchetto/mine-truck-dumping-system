## 一、项目简介

露天矿卸矿作业长期依赖人工登记与目视确认：车辆进出场无自动记录、倒矿车次靠人工点数、计量与卸矿环节相互割裂、异常停留与超限行为难以追溯，导致**计次不准、数据滞后、责任难界定**。

本项目建设的「矿井货车倒矿智能管控系统」，围绕三条主线实现作业过程数字化：

| 核心                   | 建设内容                                                     |
| ---------------------- | ------------------------------------------------------------ |
| **车牌识别与自动计次** | 卸矿平台 / 计量点 / 排土点相机接入，识别车牌与置信度，按阈值自动计次，低置信度转人工复核与补录 |
| **倒矿作业过程管控**   | 进场登记 → 计量称重 → 卸矿作业 → 离场计次 四环节闭环跟踪，输出单车耗时、点位排队与作业效率 |
| **车辆定位与告警复核** | 露天电子围栏定位、轨迹回放、偏差监控；滞留超时、点位外停留、定位偏差超限等分级告警与人工复核留痕 |

系统由**服务端 Web 管理端**、**可视化看板（大屏）**、**移动端 H5** 三部分构成，全部内网部署，共用同一套业务接口与账号权限体系。

## 六、文档与数据口径

1. **三份原始文档**为需求基线的唯一来源：招标书（甲方要求）、投标书（乙方承诺）、技术开发（委托）合同（法律约定）。三者冲突时，以合同或补充协议为准，未确认前一律标注「待确认」。
2. **页面数值全部为演示数据**：车牌号（豫 C·8F23 挂等）、司机、时间、车次、重量、置信度均为模拟值，不代表真实生产数据；各页页脚与顶栏均有「演示数据」标注。
3. **关键业务口径**（供开发与测试对齐）：

| 口径           | 取值                                                         |
| -------------- | ------------------------------------------------------------ |
| 自动计次阈值   | 置信度 ≥ 90%                                                 |
| 人工复核区间   | 置信度 70%–90%，复核时限 20 秒/条                            |
| 识别失败       | 置信度 < 70%，转人工补录                                     |
| 重复计数控制   | 同一车辆 5 分钟内去重                                        |
| 告警分级与响应 | 紧急 2 分钟内、重要 5 分钟内                                 |
| 定位精度       | 验收底线 ≤ 10 米，刷新间隔 5 秒                              |
| 售后响应       | 7×24；一般故障 4 小时响应 / 8 小时解决，重大故障 2 小时响应 / 24 小时到场 |

> 命名说明：三份 Word 文档标题为「矿井货车倒矿**管理**系统」，页面与仓库统一采用「矿井货车倒矿**智能管控**系统」。后续对外文档建议统一为后者，避免验收时名称不一致。

## 七、版本管理规范（摘要）

完整约定见两份目录 README，此处只列仓库级规则。

### 7.1 分支模型

| 分支                                     | 用途                                           |
| ---------------------------------------- | ---------------------------------------------- |
| `main`                                   | 稳定基线，可演示、可评审的版本，按里程碑打标签 |
| `develop`                                | 日常集成分支，评审前由 `main` 合入             |
| `feature/proto-*`、`feature/wireframe-*` | 单页面 / 单模块迭代                            |
| `fix/*`                                  | 缺陷修复                                       |
| `docs/*`                                 | 文档与 README 维护                             |

### 7.2 提交信息

格式 `type(scope): 简述`，scope 取 `prototype` / `wireframe` / `docs` / `repo`，一次提交只做一件事。

```bash
git commit -m "feat(wireframe): 完成 8 个页面低保真线框"
git commit -m "feat(prototype): 完成管理端 8 个页面高保真原型"
git commit -m "docs(repo): 编写仓库根目录 README"
```

### 7.3 版本标签与里程碑

| 标签               | 对应阶段      | 含义                                         |
| ------------------ | ------------- | -------------------------------------------- |
| `v0.9.0-wireframe` | 需求基线 V0.9 | 线框评审版（覆盖 6/8 模块）                  |
| `v0.9.0-prototype` | 需求基线 V0.9 | 高保真原型评审版                             |
| `v1.0.0-prototype` | 基线冻结 V1.0 | 评审意见闭环后的原型冻结版，作为开发对照基准 |

### 7.4 忽略规则

仓库根目录 `.gitignore` 至少包含：

```gitignore
# 系统与编辑器
.DS_Store
Thumbs.db
desktop.ini
.vscode/
.idea/

# Office 临时锁文件（打开 Word 时自动生成）
~$*

# 依赖与构建产物
node_modules/
dist/
```

> `招投标书及合同，需求文件/` 下现有 3 个 `~$…docx` 锁文件，属于本地打开文档时产生的临时文件，**不应提交**。

## 八、实验内容与提交计划

### 8.1 实验目标

以本系统为载体，练习「**需求文档 → 低保真线框 → 高保真原型**」三层基线的版本化协作：分支开发、增量提交、里程碑标签、变更可追溯。

### 8.2 建议提交序列

| 阶段          | 建议提交信息                                     | 产出                        |
| ------------- | ------------------------------------------------ | --------------------------- |
| 1. 建库与基线 | `chore(repo): 初始化仓库与项目文档`              | 3 份需求文档 + `.gitignore` |
| 2. 线框演进   | `feat(wireframe): 完成 8 个页面低保真线框`       | `线框页面/*.html`           |
| 3. 线框评审   | `docs(wireframe): 编写线框页面 README`           | 线框规范与覆盖度分析        |
| 4. 原型演进   | `feat(prototype): 完成管理端 8 个页面高保真原型` | `原型页面/**`               |
| 5. 原型评审   | `docs(prototype): 编写原型页面 README`           | 视觉与交互规范              |
| 6. 打标签     | `git tag -a v0.9.0-prototype`                    | 评审版本快照                |
| 7. 迭代补充   | `feat(wireframe): 新增基础数据管理线框页`        | 补齐缺失模块                |
| 8. 仓库总览   | `docs(repo): 编写仓库根目录 README`              | 本文件                      |

### 8.3 首次推送

```bash
git init
git branch -M main
git add .
git commit -m "chore(repo): 初始化仓库与项目文档"
git remote add origin https://github.com/<用户名>/<仓库名>.git
git push -u origin main
```

### 8.4 交付物清单

- [ ] GitHub 仓库地址与访问权限（私有仓库需邀请评阅人）
- [ ] 至少 8 次语义化提交记录（含 `feat` / `docs` / `chore` 三类以上）
- [ ] 2 个目录 README + 1 个根 README
- [ ] 至少 2 个版本标签（`v0.9.0-wireframe`、`v0.9.0-prototype`）
- [ ] 分支合并记录（至少 1 次 `--no-ff` 合并）
- [ ] 实验报告：提交历史截图、分支图、标签说明与问题复盘
